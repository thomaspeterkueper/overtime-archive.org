# EXT-ECO-OTA-20261028-001 – review-Block ins Content-Schema

## Anlass

[ECO-ARC-0037-2026-DE](https://github.com/thomaspeterkueper/kueper-ecosystem/blob/main/decisions/ECO-ARC-0037-2026-DE.md) führt eine wiederkehrende Begutachtung aller nicht abgeschlossenen Dokumente ein (spätestens alle 12 Monate). Der nächste Termin steht im Frontmatter jedes Dokuments.

## Gewünschte Änderung

In `src/content.config.ts` (und, falls noch genutzt, `src/content/config.ts`) einen optionalen Block ergänzen:

```ts
review: z.object({
  last: z.string().regex(/^\d{4}-\d{2}-\d{2}$/).optional(),
  next: z.string().regex(/^\d{4}-\d{2}-\d{2}$/).optional(),
  reason: z.string().optional(),
  abgeschlossen: z.boolean().default(false),
}).optional(),
```

Das bestehende Feld `provenance.reviewedAt` bleibt unverändert erhalten. Keine Dokumente massenhaft anfassen – die Termine setzt die tägliche Begutachtung nach und nach.

## Begründung

Ohne Schemaeintrag würde Astro den Block stillschweigend verwerfen; mit Schema ist er typisiert und auf der Seite nutzbar (z. B. später „nächste Prüfung: …“ anzeigen).

## Erwartetes Ergebnis

- Schema enthält den optionalen `review`-Block.
- `npm run build` (bzw. das vorhandene Prüfskript) läuft grün.
- Ein Dokument mit Beispiel-Block baut fehlerfrei.

## Erledigt

Status: done – Ökosystem-Kreislauf (Claude), 14.11.2026.

## Umgesetzt

- `src/content.config.ts`: optionaler Block `review` (`last`, `next` als JJJJ-MM-TT, `reason`, `abgeschlossen` mit Standard `false`) in der Collection `documents`; `provenance.reviewedAt` unverändert.
- `src/content/config.ts` nicht geändert: Astro 6 liest nur noch `src/content.config.ts`, der Altpfad wird von keinem Skript genutzt.
- Keine Dokumente massenhaft angepasst.
- Geprüft: `npm run verify` grün (353 Seiten, Linkprüfung bestanden); ein Dokument mit Beispiel-Block baut fehlerfrei, ein ungültiges Datum (`2027-1-1`) bricht den Build wie erwartet ab. Der Beispiel-Block wurde nicht eingecheckt.
